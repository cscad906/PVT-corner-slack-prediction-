# PrimeTime 담당자께 드리는 요청

PVT 코너별 타이밍 데이터 추출용 스크립트입니다. **표준 PrimeTime 명령만 씁니다.**
아래에 무엇을 읽고 무엇을 쓰는지, 세션에 어떤 영향이 있는지 정리했습니다.

---

## 요청드리는 것

pt_shell 에서 **`source` 두 줄**입니다.

```tcl
pt_shell> source <경로>/example/02_round2_all.tcl
pt_shell> source <경로>/round2/run_pt1_xtalk_calc.tcl
pt_shell> source <경로>/round2/run_pt2_xtalk_windows.tcl
```

(사이사이 저희 쪽에서 파이썬 후처리를 하므로 세 번에 나눠 부탁드립니다.)

---

## 왜 손으로 못 치는가

명령 **종류**가 특수해서가 아니라 **개수** 때문입니다. 코너 하나당:

| 단계 | 명령 | 횟수 |
|---|---|---|
| 1회차 | `report_timing` | 코너당 1 |
| 2회차 | `report_timing -from/-through/-to` | **294** |
| crosstalk 1차 | `report_delay_calculation -crosstalk` | **788** |
| crosstalk 2차 | `get_attribute` | **1,378** |

고정된 경로 집합을 **코너마다 똑같이** 재측정해야 코너 간 비교가 되는데,
그러려면 경로마다 `-from/-through/-to` 를 걸어야 합니다. 그래서 개수가 커집니다.

---

## 쓰는 명령 전부

이게 전부입니다. 커스텀 명령이나 외부 도구는 없습니다.

```
read_verilog        current_design      link_design
read_sdc            read_parasitics     set_propagated_clock
update_timing       remove_design       set_app_var        get_app_var
report_timing       report_attribute    report_delay_calculation
get_pins            get_nets            get_attribute      get_designs
all_clocks          sizeof_collection   index_collection   get_object_name
redirect            source              file / open / puts / glob   (Tcl 기본)
```

`write_*` 계열은 **하나도 쓰지 않습니다.** (`write_sdf`, `write_changes`,
`save_session` 등 없음)

---

## 세션에 미치는 영향 — **전용 pt_shell 을 권합니다**

스크립트가 **코너마다 디자인을 다시 읽습니다.**

```tcl
remove_design -all
read_verilog / link_design / read_sdc / read_parasitics
update_timing
```

코너(전압·온도)마다 db 가 달라 링크를 다시 해야 하기 때문입니다.
**따라서 다른 작업과 같은 세션에서 돌리면 그 작업이 날아갑니다.**
새 pt_shell 을 하나 띄워서 거기서만 돌려 주시면 감사하겠습니다.

바꾸는 app var 는 두 개입니다.

```tcl
set_app_var si_enable_analysis true              # crosstalk 계산에 필요
set_app_var timing_save_pin_arrival_and_slack true
```

---

## 읽는 것 / 쓰는 것

**읽기 (수정하지 않음)**

```
넷리스트 (.v)    SDC    SPEF    라이브러리 db
```

**쓰기 (지정한 출력 폴더 안에만)**

```
<코너>.rpt          report_timing 결과
pin_attr.txt        report_attribute 결과
net_attr.txt        report_attribute 결과
corner_info.tcl     어떤 db/spef 로 만들었는지 기록 (10줄)
xtalk/*.rpt|tsv     crosstalk 중간 파일
```

**설계 데이터를 고치거나 저장하지 않습니다.** `write_*` 계열 명령을 쓰지 않습니다.

## 소요 시간

코너 하나당 대략:

| | |
|---|---|
| 디자인 로드 | 약 30초 |
| 2회차 측정 (294경로) | 약 30초 |
| crosstalk 1차 (788넷) | 약 30초 |
| crosstalk 2차 | 약 30초 |

코너 17개면 PT 총 **1시간 안쪽**입니다. 경로 수를 줄이면 더 짧아집니다.

라이선스는 pt_shell 1개 = PrimeTime 1석이고, `si_enable_analysis` 때문에
**PrimeTime-SI 1석**이 추가로 필요합니다.

## 저희가 손으로 칠 수 있는 부분

**1회차만은 명령 한 줄이라 저희가 직접 하겠습니다.** 코너를 바꿔 로드해 주시면
아래를 저희가 입력하겠습니다.

```tcl
redirect -file <어딘가>/round1/corners/<코너이름>.rpt {
  report_timing -delay_type max -path_type full_clock_expanded \
    -nets -input_pins -nosplit -significant_digits 6 \
    -nworst 3 -max_paths 100000 -slack_lesser_than 0.05
}
```

`-nets -input_pins -nosplit -path_type full_clock_expanded` **네 개는 필수**입니다.
하나라도 빠지면 뒤 단계가 진행되지 않습니다.

hold 데이터가 필요할 때는 `-delay_type min` 으로 한 세트 더 부탁드립니다.

---

## 이미 뽑아 두신 리포트가 있다면

그대로 쓸 수 있는지 **첫머리 옵션 목록**만 확인해 주시면 됩니다.
`report_timing` 이 리포트 맨 위에 자기가 쓴 옵션을 그대로 적어 둡니다.

```
Report : timing
	-path_type full_clock_expanded
	-nosplit
	-input_pins
	-nets
	...
```

위 네 개가 다 보이면 그대로 쓰겠습니다.
