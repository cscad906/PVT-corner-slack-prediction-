# PrimeTime 담당자께 드리는 요청

PVT 코너별 타이밍 데이터 추출용 스크립트입니다. **표준 PrimeTime 명령만 씁니다.**
아래에 무엇을 읽고 무엇을 쓰는지, 세션에 어떤 영향이 있는지 정리했습니다.

---

## 요청드리는 것 — 코너마다 `source` 두 줄

디자인(넷리스트/SDC/SPEF)과 그 코너의 db 를 **평소 하시던 대로 로드**해 주신
다음, **같은 pt_shell 세션에서 이어서** 아래 두 줄만 쳐 주시면 됩니다.

```tcl
pt_shell> source <경로>/fixed_paths.tcl      ;# 저희가 만들어 드린 경로 목록
pt_shell> source <경로>/xtalk_all.tcl        ;# hold 는 xtalk_all_hold.tcl
```

`cd` 하실 필요 없습니다. 뒤 파일이 앞 파일이 방금 만든 리포트를 알아서 찾습니다
(같은 세션에 남은 변수를 봅니다).

화면 마지막에 `[ OK-XTALK ]` 이 보이면 정상입니다.

### 저희가 드리는 파일은 세 개뿐입니다

| 파일 | 무엇 |
|---|---|
| `fixed_paths.tcl` | 측정할 경로 목록. 저희가 1회차 리포트를 합쳐 만들어 드립니다 |
| `pt/xtalk_all.tcl` | crosstalk 추출 (setup 용, `-delay_type max`) |
| `pt/xtalk_all_hold.tcl` | 같은 것의 hold 판 (`-delay_type min`). **두 파일은 한 줄만 다릅니다** |

### 결과가 어디에 쌓이나

실행하신 자리 아래, **로드하신 db 이름**으로 폴더가 생깁니다.

```
<db이름>/xtalk/          setup
<db이름>_hold/xtalk/     hold
```

db 이름으로 갈리므로 **한 자리에서 코너를 여러 개 돌리셔도 서로 덮어쓰지
않습니다.** (`link_path` 에서 db 이름을 읽습니다)

한 가지만 봐 주십시오. `fixed_paths.tcl` 이 만드는 리포트 이름은 **지금 계신
폴더 이름**을 따라갑니다.

```
  이번 코너 : TT_0p6V_25C   ->  TT_0p6V_25C.rpt
  (위 이름이 방금 로드한 db 와 다르면 지금 멈출 것)
```

이 줄이 화면에 찍힙니다. 코너마다 이름이 갈리게 하시려면 **코너별 폴더에서
돌리시거나**, `fixed_paths.tcl` 맨 위 `set CORNER` 한 줄을 코너 이름으로
고쳐 주시면 됩니다.

## 세션 준비 — app var 두 개

**스크립트가 바꾸지 않습니다.** 디자인을 로드하실 때 켜 주시기를 부탁드립니다.

```tcl
set_app_var si_enable_analysis true                # crosstalk 계산에 필요
set_app_var timing_save_pin_arrival_and_slack true # 핀별 도착시각/slew 조회에 필요
```

`si_enable_analysis` 가 꺼져 있으면 crosstalk 값이 **전부 0** 으로 나옵니다.
스크립트가 시작할 때 확인해서 경고를 띄웁니다만, 값 자체는 못 살립니다.

SPEF 는 coupling 이 살아 있는 것이어야 합니다
(`read_parasitics -keep_capacitive_coupling`, StarRC `COUPLING_CAP: YES`).

---

## 세션에 미치는 영향 — **없습니다**

드리는 두 파일은 **읽기만 합니다.** 아래를 하나도 하지 않습니다.

```
remove_design       read_verilog / link_design / read_sdc / read_parasitics
set_app_var         update_timing
write_* 계열        save_session
```

즉 **이미 올려 두신 디자인을 그대로 두고 리포트만 뽑습니다.** 돌리고 나서도
세션 상태가 그대로이므로, 이어서 다른 작업을 하셔도 됩니다.

(다만 코너를 바꾸실 때는 db 를 갈아 끼우셔야 하므로, 그 부분은 평소 쓰시는
방식대로 해 주시면 됩니다.)

---

## 쓰는 명령 전부

이게 전부입니다. 커스텀 명령이나 외부 도구는 없습니다.

```
report_timing       report_delay_calculation
get_pins            get_nets            get_attribute       get_app_var
get_designs         get_object_name     sizeof_collection   index_collection
redirect            source              file / open / gets / puts   (Tcl 기본)
```

---

## 왜 손으로 못 치는가

명령 **종류**가 특수해서가 아니라 **개수** 때문입니다. 코너 하나당:

| 단계 | 명령 | 횟수 |
|---|---|---|
| 1회차 | `report_timing` | 코너당 1 |
| `fixed_paths.tcl` | `report_timing -from/-through/-to` | **294** |
| `xtalk_all.tcl` | `report_delay_calculation -crosstalk` | **788** |
| `xtalk_all.tcl` (이어서) | `get_attribute` | **1,378** |

고정된 경로 집합을 **코너마다 똑같이** 재측정해야 코너 간 비교가 되는데,
그러려면 경로마다 `-from/-through/-to` 를 걸어야 합니다. 그래서 개수가 커집니다.

(예전에는 crosstalk 때문에 세션을 한 번 더 나눠 부탁드려야 했습니다. 계산 결과에서
aggressor 이름을 뽑아 다시 물어봐야 했기 때문입니다. 지금은 `xtalk_all.tcl` 이
자기가 받은 출력에서 직접 긁어 이어서 처리하므로, **세션 한 번에 끝납니다.**)

## 읽는 것 / 쓰는 것

**읽기 (수정하지 않음)**

```
이미 로드된 디자인 (넷리스트 / SDC / SPEF / 라이브러리 db)
fixed_paths.tcl   -- 저희가 드린 경로 목록
```

**쓰기 (실행하신 자리 아래에만)**

```
<코너>.rpt                        report_timing 결과 (fixed_paths.tcl)
<db이름>/xtalk/unique_contexts.tsv      물어본 넷 목록
<db이름>/xtalk/context_raw.rpt          report_delay_calculation 원문
<db이름>/xtalk/victim_windows.tsv       victim 핀 도착시각/slew
<db이름>/xtalk/aggressor_windows.tsv    aggressor 드라이버 도착시각/slew
```

**설계 데이터를 고치거나 저장하지 않습니다.** `write_*` 계열 명령을 쓰지 않습니다.

## 소요 시간

코너 하나당 대략:

| | |
|---|---|
| `fixed_paths.tcl` (294경로) | 약 30초 |
| `xtalk_all.tcl` — crosstalk (788넷) | 약 30초 |
| `xtalk_all.tcl` — 도착시각/slew (이어서) | 약 30초 |

디자인 로드 시간(코너당 약 30초)은 별도입니다. 코너 17개면 PT 총 **1시간 안쪽**
입니다. 경로 수를 줄이면 더 짧아집니다.

라이선스는 pt_shell 1개 = PrimeTime 1석이고, `si_enable_analysis` 때문에
**PrimeTime-SI 1석**이 추가로 필요합니다.

## 1회차 — 이건 명령 한 줄이라 저희가 직접 치겠습니다

`fixed_paths.tcl` 을 만들려면 먼저 **코너마다 위반/위험 경로 목록**이 필요합니다.
코너를 바꿔 로드해 주시면 아래를 저희가 입력하겠습니다.

```tcl
redirect -file <어딘가>/round1/corners/<코너이름>.rpt {
  report_timing -delay_type max -path_type full_clock_expanded \
    -nets -input_pins -nosplit -significant_digits 6 \
    -nworst 3 -max_paths 100000 -slack_lesser_than 0.05
}
```

`-nets -input_pins -nosplit -path_type full_clock_expanded` **네 개는 필수**입니다.
하나라도 빠지면 뒤 단계가 진행되지 않습니다.

hold 데이터가 필요할 때는 `-delay_type min` 으로 한 세트 더 부탁드립니다.
setup 과 hold 는 완전히 별개 2세트라 섞이면 안 됩니다.

### 이미 뽑아 두신 리포트가 있다면

그대로 쓸 수 있는지 **첫머리 옵션 목록**만 확인해 주시면 됩니다.
`report_timing` 이 리포트 맨 위에 자기가 쓴 옵션을 그대로 적어 둡니다.

```
Report : timing
	-path_type full_clock_expanded
	-nosplit
	-input_pins
	-nets
	...
```

위 네 개가 다 보이면 그대로 쓰겠습니다.

## 한 가지 더 — Cpin 표를 부탁드립니다

핀별 입력 capacitance 값이 필요한데, `report_timing` 리포트에는 안 찍힙니다.
아래 둘 중 **편하신 쪽 하나**로 뽑아 주시면 됩니다. 값은 같습니다.

```tcl
# (가) 설계 핀 -- 제일 정확합니다. 핀 수만큼 나옵니다
foreach_in_collection p [get_pins -hierarchical *] {
    puts "[get_object_name $p]\t[get_attribute -quiet $p pin_capacitance_max]"
}

# (나) 라이브러리 핀 -- 훨씬 짧습니다(셀 종류 수만큼)
foreach_in_collection p [get_lib_pins *] {
    puts "[get_object_name $p]\t[get_attribute -quiet $p pin_capacitance]"
}
```

- (나)에서는 attribute 이름이 `pin_capacitance` 입니다.
  `capacitance` 나 `pin_capacitance_max` 는 빈 값으로 나옵니다.
- 헤더는 없어도 되고, 구분자는 탭·쉼표·띄어쓰기 아무거나 됩니다.
- **열이 더 있어도 됩니다.** `핀이름  pin_cap  wire_cap` 처럼 나와도 저희 쪽에서
  어느 열이 Cpin 인지 알아서 고릅니다.
- 다만 **셀 이름만** 있거나 **넷 이름**만 있는 표는 못 씁니다. Cpin 은 핀마다
  다른 값이라 핀 구분이 있어야 합니다.

**코너마다 한 번씩** 부탁드립니다. 0.6V 와 0.8V 를 재 보면 값이 중앙값 5.95%,
최대 8.27% 차이가 났습니다(788개 중 176개만 동일). 한 코너 것을 전 코너에 돌려
쓰면 그만큼 틀린 값이 들어갑니다.

## 저희가 받아 가는 것 (코너마다)

```
<코너>.rpt                  fixed_paths.tcl 산출물
<db이름>/xtalk/             파일 4개 (위 '쓰는 것' 참조)
Cpin 표                     위 (가) 또는 (나)
```

SPEF 는 현장에 있는 것을 그대로 쓰겠습니다.

## 문의

스크립트가 하는 일에 의문이 있으시면 각 파일 맨 위 주석에 설명이 있습니다.
`fixed_paths.tcl`, `pt/xtalk_all.tcl` 순으로 보시면 흐름이 보입니다.

문제가 생기면 화면 마지막에 `E-` 또는 `W-` 로 시작하는 **코드**가 찍힙니다
(예: `E-NORPTFILE`, `E-NODESIGN`). 그 코드 하나만 알려 주시면 저희가 바로
어디가 막혔는지 알 수 있습니다.
