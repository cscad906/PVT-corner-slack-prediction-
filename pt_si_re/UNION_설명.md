# `1_union.py` 설명서

코딩을 모르는 사람이 읽고 운용할 수 있게 쓴 문서입니다.
**화면에 나오는 숫자를 어떻게 읽는지**와 **이상할 때 무엇을 하는지**가 핵심입니다.

---

## 1. 이게 왜 필요한가

코너(전압·온도·RC 조합)마다 **위험한 경로가 다릅니다.**

```
0.8V 에서 나쁜 경로 :  A, B, C
0.6V 에서 나쁜 경로 :  B, C, D, E      <- A 는 괜찮아지고 D, E 가 새로 나빠짐
```

어느 한 코너만 보고 경로를 고르면 나머지를 놓칩니다.
그래서 **전 코너의 목록을 합친 뒤(A,B,C,D,E), 그 전체를 모든 코너에서 똑같이 다시
측정**합니다. 그래야 "같은 경로가 전압에 따라 어떻게 변하는가" 를 볼 수 있습니다.

이 스크립트가 그 **합치는 일**을 합니다.

---

## 2. 무엇을 넣고 무엇이 나오나

```
넣는 것    round1/corners/ 폴더 안의 .rpt 파일들   (코너마다 하나)
           파일 이름이 그대로 코너 이름이 됩니다

나오는 것  union_paths.tsv    합쳐진 경로 목록 (엑셀로 열어 보는 용도)
           fixed_paths.tcl    2회차에 pt_shell 에서 source 할 파일
```

실행:

```bash
$PY 1_union.py --dir round1/corners
```

---

## 3. 같은 경로인지 어떻게 판단하나

**세 가지가 모두 같아야** 같은 경로로 봅니다.

```
① 시작 플립플롭      FF_A
② 끝 플립플롭        FF_B
③ 그 사이를 지나는 핀 전부   U1/A → U1/X → U2/B → U2/X → ...
```

③까지 보는 이유: **같은 FF 쌍 사이에도 지나는 길이 여러 개** 있습니다.
①②만 보면 서로 다른 길을 같은 경로로 착각합니다.

여기에 더해 **rise/fall 방향**도 기록합니다. 신호가 올라가며 지나는지 내려가며
지나는지가 코너마다 뒤바뀔 수 있는데, 그러면 같은 번호에 다른 것이 측정됩니다.
방향까지 고정하면 그 일이 생기지 않습니다.

## 4. 화면 읽는 법

```
  코너                                      리포트       사용       제외
  --------------------------------------------------------------
  tt0p8v25c_Cnom                          3000     3000        0
  tt0p7v25c_Cnom                          3000     2998        2
  tt0p6v25c_Cnom                          3000     3000        0

--------------------------------------------------------------------
  합집합 경로 : 5,412개
  결과 목록   : round1/corners/union_paths.tsv
  2회차 tcl   : round1/corners/fixed_paths.tcl
  rise/fall 고정 : 5412 / 5412 경로
--------------------------------------------------------------------
  한 코너에서만 나온 경로 : 3,180  (합집합이 필요한 이유)
  모든 코너에 나온 경로   : 421
```

| 항목 | 뜻 | 정상 범위 |
|---|---|---|
| **리포트** | 그 파일에 있던 경로 수 | `-max_paths` 로 준 값 이하 |
| **사용** | 실제로 합집합에 넣은 수 | 리포트와 같거나 조금 적음 |
| **제외** | 버린 수 | **0 이거나 아주 적어야 정상** |
| **합집합 경로** | 최종 목록 크기 | 코너별 수보다 크고, 전부 더한 값보다 작음 |
| **rise/fall 고정** | 방향까지 고정된 경로 수 | **전체와 같아야 정상** |
| **한 코너에서만** | 그 코너에만 있던 경로 | 많을수록 합집합의 효과가 큼 |
| **모든 코너에** | 전 코너 공통 경로 | 적어도 이상하지 않음 |

### 숫자가 이러면 정상입니다

```
코너 3개 × 각 3000경로  →  합집합 5,412
```
3,000보다 크고 9,000보다 작으면 정상입니다.
- 합집합이 **3,000 근처** = 코너들이 거의 같은 경로를 봄 (전압 차이가 작을 때)
- 합집합이 **9,000 근처** = 코너마다 완전히 다른 경로를 봄

### 숫자가 이러면 이상합니다

| 증상 | 무슨 일인가 | 할 일 |
|---|---|---|
| **제외**가 리포트와 거의 같음 | 핀 정보가 없는 리포트 | `report_timing` 에 `-input_pins` 추가해 다시 |
| **제외**가 수십~수백 개 | 포트에서 시작/끝나는 경로가 많음 | 대개 정상. FF 사이가 아닌 경로는 원래 제외됨 |
| **합집합**이 코너 하나 크기와 같음 | 모든 코너가 같은 경로를 봄 | 코너들이 실제로 비슷한지 확인. 같은 파일을 복사한 건 아닌지 |
| **rise/fall 고정**이 전체보다 적음 | 일부 경로에 방향 표시가 없음 | 리포트를 다시 뽑아 보고, 그래도 적으면 가져오세요 |
| **리포트** 수가 코너마다 `-max_paths` 와 정확히 같음 | 잘렸을 수 있음 | `-max_paths` 를 키워 다시 뽑는 것을 권함 |

## 5. 제외된 경로 — 이유별 안내

제외가 있으면 화면에 이유가 함께 나옵니다. 사유는 **두 가지뿐**입니다.

### 핀 연결을 못 찾음

경로의 데이터 구간(시작 FF 에서 신호가 나와 끝 FF 로 들어가기까지)을 못 찾은 경우입니다.

| 개수 | 뜻 | 할 일 |
|---|---|---|
| 몇 개 ~ 수십 개 | 칩 바깥 포트와 연결된 경로. FF 사이가 아니라 원래 제외됨 | **정상. 그냥 두세요** |
| 리포트의 거의 전부 | 핀 줄 자체가 없음 | `report_timing` 에 `-input_pins` 를 넣어 다시 |

> 참고: FF 의 출력·입력 핀 이름(`Q`/`D`, `QB`/`DIN`, `Z`/`A` 등)은 라이브러리마다
> 다른데, 이 스크립트는 **이름이 아니라 위치로** 구간을 찾으므로 어떤 라이브러리든
> 동작합니다. 핀 이름이 달라서 실패하는 일은 없습니다.

### slack 줄이 없음

경로 블록 끝의 `slack (...)` 줄을 못 만난 경우입니다.

| 개수 | 뜻 | 할 일 |
|---|---|---|
| 1~2개 | 파일 맨 끝이 잘림 | **무시해도 됩니다** |
| 여러 개 | `-nosplit` 이 빠져 줄이 접힘 | 옵션 넣어 다시 뽑기 |

### 버린 비율이 크면 따로 경고합니다

```
  [ 주의 ] 버린 경로가 52개로 적지 않습니다 (쓴 것 117개).
           리포트 형식 문제일 수 있습니다. 아래 옵션을 모두 넣었는지
           확인하세요:
             -nets -input_pins -nosplit -path_type full_clock_expanded
```

이 경고가 뜨면 **거의 항상 리포트 옵션 문제**입니다. 위 네 개를 다 넣고 다시 뽑으세요.

## 6. 실패 화면과 대처

### `.rpt 파일이 없습니다`
```
[ 실패 ] round1/corners 안에 .rpt 파일이 없습니다.
```
폴더 경로가 틀렸거나 파일을 아직 안 넣었습니다. `--dir` 뒤 경로를 확인하세요.

### `쓸 수 있는 경로가 하나도 없습니다`
```
[ 실패 ] 쓸 수 있는 경로가 하나도 없습니다.
         report_timing 에 -input_pins 가 빠졌을 가능성이 큽니다.
```
가장 흔한 원인입니다. 아래 옵션으로 리포트를 다시 뽑으세요.
```tcl
report_timing -delay_type max -path_type full_clock_expanded \
  -nets -input_pins -nosplit \
  -nworst 3 -max_paths 3000 -slack_lesser_than 0.05 > round1/corners/<코너>.rpt
```

## 7. 직접 확인해 보는 방법 (코드 없이)

### 리포트에 경로가 몇 개인지
```bash
grep -c "Startpoint:" round1/corners/<코너>.rpt
```
이 숫자가 화면의 **리포트** 열과 같아야 합니다.

### 핀 줄이 들어 있는지 (`-input_pins` 확인)
```bash
grep -c "/.* (" round1/corners/<코너>.rpt
```
0 이면 핀 정보가 없는 것입니다.

### 합집합 결과를 엑셀로
`union_paths.tsv` 를 엑셀에서 열면 이렇게 생겼습니다.

| path_idx | startpoint | endpoint | n_through | n_corners_seen | n_corners_violating | worst_slack | worst_corner | slack__코너1 | slack__코너2 | … |
|---|---|---|---|---|---|---|---|---|---|---|
| 1 | FF_A | FF_B | 38 | 3 | 2 | -0.185816 | tt0p6v25c | 0.21 | 0.05 | -0.18 |

- `n_corners_seen` : 몇 개 코너의 목록에 있었나
- `n_corners_violating` : 그중 slack 이 음수(진짜 위반)인 코너 수
- `slack__<코너>` : 코너별 slack. **빈칸이면 그 코너 목록에는 없었다**는 뜻입니다
- `worst_slack` 오름차순으로 정렬돼 있어, 위쪽이 가장 위험한 경로입니다

**필터로 볼 만한 것**
- `n_corners_violating` > 0 → 실제로 위반한 적이 있는 경로
- `n_corners_seen` = 1 → 한 코너에서만 나온 경로 (합집합 덕에 살아남은 것)

### 2회차 tcl 에 경로가 몇 개 들어갔는지
```bash
grep -c "^  {{" round1/corners/fixed_paths.tcl
```
화면의 **합집합 경로** 수와 같아야 합니다.

## 8. 경로 개수 걱정은 안 하셔도 됩니다

실측입니다.

| 입력 | 처리 시간 |
|---|---|
| 코너 3개 × 400경로 (1,200) | 0.3초 |
| 코너 3개 × 2,500경로 (7,500) | **2.5초** |

경로가 몇 만 개가 되어도 수십 초 수준입니다. 메모리도 경로 수에 비례할 뿐이라
일반적인 규모에서는 문제가 없습니다.

2회차 PT 재측정도 **868경로에 3초**로 측정됐습니다(초당 약 290경로).
경로 1만 개면 40초 정도입니다.

## 9. 옵션

| 옵션 | 뜻 | 언제 쓰나 |
|---|---|---|
| `--dir <폴더>` | 리포트가 있는 폴더 | 항상 |
| `--slack-max <값>` | 이 값보다 slack 이 큰 경로는 제외 | 리포트를 넓게 뽑아 놓고 여기서 좁힐 때 |
| `--no-edge` | rise/fall 고정을 끔 | 방향 고정 때문에 2회차에서 경로가 안 잡힐 때만 |

`--no-edge` 는 기본으로 쓰지 마세요. 방향을 고정하지 않으면 코너마다 다른 것이
측정될 수 있습니다.
