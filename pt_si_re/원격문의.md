# 막혔을 때 — 화면 읽는 법과 원격 문의

현장에서는 화면을 복사하기도, git push 하기도 어렵습니다.
그래서 **화면만 읽고 대부분 스스로 해결**할 수 있게, 그래도 안 되면 **코드 하나만
전달**하면 되게 만들어 두었습니다.

---

## 스크립트가 끝나면 이런 게 나옵니다

### 잘 됐을 때

```
==================================================================
  정상 종료           [ OK-CPIN ]
==================================================================
```

다음 명령으로 넘어가시면 됩니다. 바로 위에 다음 명령이 적혀 있습니다.

### 문제가 있을 때

```
==================================================================
  문제 발생
    무엇이   : SPEF 에서 저항(Res)을 하나도 못 구했습니다
    하실 일  : SPEF 가 이 리포트와 같은 디자인/코너인지 확인해 주세요.

    에러 코드: E-RES0
    (해결이 안 되면 이 코드를 알려주세요)
==================================================================
```

**`하실 일` 을 먼저 해 보세요.** 대부분 그걸로 풀립니다.
안 되면 그때 `에러 코드` 를 저에게 알려주시면 됩니다.

### 결과는 나왔지만 확인이 필요할 때

```
==================================================================
  확인 필요
    무엇이   : Dist/Res 가 비어 있는 줄이 많습니다
    하실 일  : 9_diagnose.py 를 돌리면 원인을 A/B/C 로 나눠 줍니다.

    에러 코드: W-RES
==================================================================
```

`확인 필요` 는 **파일은 만들어졌습니다.** 다만 데이터가 불완전하니 원인을 보는 게 좋습니다.

---

## 저에게 전달할 때

코드만 있으면 됩니다.

```
2b 에서 E-RES0 떴어
```

숫자를 덧붙이면 더 정확합니다. 코드 위쪽에 숫자가 있는 줄이 나옵니다.

```
2b 에서 E-RES0, (net) 105337줄인데 Res 0개
W-RES 인데 Res 가 34% 비었대
```

`확인 필요(W-)` 인 경우는 **몇 퍼센트인지**가 중요합니다.

## 그래도 안 풀리면 — 상황 요약

```bash
python3 8_snapshot.py --dir <문제가 난 폴더>
```

환경, 파일 목록, 리포트 형식, SPEF 헤더, 결과 상태를 100줄로 정리해 줍니다.
화면에서 아래 부분만 읽어 주셔도 됩니다.

- `>>` 로 시작하는 줄 (자동 판정)
- `3-1. timing.rpt 형식` 아래 숫자 3개
- `4. 결과 파일 상태` 아래 줄들

설계 이름이 밖으로 나가면 안 되면 `--mask` 를 붙이세요. 이름이 `<name:47>` 로 가려집니다.

## 요약

| 화면 | 하실 일 |
|---|---|
| `정상 종료 [ OK-… ]` | 다음 명령으로 |
| `확인 필요` | `하실 일` 대로. 그래도면 코드 + 비율 알려주기 |
| `문제 발생` | `하실 일` 대로. 그래도면 코드 알려주기 |
| 코드로 안 풀림 | `8_snapshot.py` 돌리고 `>>` 줄과 숫자 읽어주기 |

전체 코드 목록과 자세한 조치는 `코드표.md` 에 있습니다.
