### xtalk_all: 리포트 이름을 `fixed_setup.rpt` 로 박아 둔다

현장 코너 폴더 이름이 `fixed_setup` 이라 리포트가 `fixed_setup.rpt` 로 나온다.
그 이름을 기본값으로 박아, **파일을 바로 읽고 첫 줄 검사를 아예 건너뛴다.**

```tcl
set RPT_FILE   "fixed_setup.rpt"   ;# 상대 이름 = 현재 폴더 기준
```

리포트를 못 찾던 문제(못 열거나 첫 줄 판정에서 걸리던 것)를 통째로 우회한다.

**없으면 멈추지 않는다.** 예전에는 `RPT_FILE` 에 적힌 파일이 없으면
`E-NORPTFILE` 로 끝났는데, 이제는 자동 탐색으로 넘어간다. 이름이 다른 코너
폴더에서 돌릴 때 막히면 곤란하기 때문이다. 조용히 넘어가지는 않는다.

```
NOTE: RPT_FILE says "fixed_setup.rpt" but that file is not in /.../B.
      falling back to searching this directory.
found the fixed-path report : tt0p7v25c_Cnom.rpt
```

찾는 순서:

| | 무엇 | 첫 줄 검사 |
|---|---|---|
| 1 | `RPT_FILE` 이름을 바로 읽음 | 안 함 |
| 2 | 폴더에서 `### FIXED_PATH` 로 시작하는 `.rpt` | 함 |
| 3 | 없으면 `E-NORPTFILE` + 파일별 탈락 사유 | -- |

1번에서 검사를 건너뛰므로 엉뚱한 파일이어도 일단 읽는다. 그건 뒤에서 잡힌다 --
디자인이 다르면 `E-DESIGNMISMATCH`, `### FIXED_PATH` 가 없으면 `W-NOPATHS`.

**실제 PT 로 검증했다.** `fixed_setup.rpt` 가 있는 폴더는 바로 읽어 `OK-XTALK`,
이름이 다른 폴더는 NOTE 를 찍고 자동 탐색으로 넘어가 `OK-XTALK` 였다.

자동 탐색만 쓰시려면 `set RPT_FILE ""` 로 비우면 된다.

### xtalk_all: 리포트 후보가 **왜 탈락했는지** 남긴다

리포트를 못 찾는 일이 있었는데, 파일은 폴더에 있고 첫 줄도 정확했다. 원인은
후보를 고르는 자리에서 **못 여는 경우를 조용히 삼키고 있었던 것**이다.

```tcl
if {[catch {set fh [open $f r]}]} continue      ;# 이유를 안 남기고 건너뜀
```

그러면 파일은 목록에 보이는데 후보에서 빠지고, 로그에는 `none of them qualify`
라고만 남는다. 로그만 보는 쪽에서는 손쓸 수가 없다.

이제 파일마다 사유를 한 줄씩 찍는다.

```
             .rpt files that are here, and why each was rejected:
               banner.rpt
                   first line is not '### FIXED_PATH' -- "****************************"
               noperm.rpt
                   could not open -- couldn't open "noperm.rpt": permission denied
```

| 사유 | 뜻 |
|---|---|
| `could not open -- <PT 메시지>` | 권한, 깨진 링크, 마운트 문제 |
| `could not read -- <메시지>` | 열렸는데 읽다 실패 |
| `first line is not '### FIXED_PATH' -- "<첫 50자>"` | 첫 줄을 그대로 보여 준다 |
| `skipped -- this is our own output` | `*by_path.rpt` |

**BOM 과 앞 공백도 걷어낸다.** 눈에 안 보이는 문자 때문에 탈락하던 것을 없앴다.
후보 검사와 `xt_build_contexts` **양쪽에 같은 규칙**을 넣었다 -- 한쪽만 넣었더니
"통과는 했는데 경로를 0개로 읽는" 어긋난 상태가 나와서 시험 중에 잡았다.

**실제 PT 로 검증했다** (BoomCoreV3 / TT_0p7V_25C / `pt_shell V-2023.12-SP4`).
권한 없는 파일과 배너로 시작하는 파일을 한 폴더에 두고 돌렸더니, 위 형태로
사유가 각각 찍혔다.

hold 판도 `dev/make_hold.py` 로 다시 만들었다. 두 tcl 은 재전달이 필요하다.

### xtalk_all: 화면 출력을 스스로 파일로 남긴다 (`xtalk_all_run.log`)

돌리는 분과 받는 분이 다르고 **받는 쪽은 화면을 못 본다.** `pt_shell
-output_log_file ...` 로 돌려 달라거나 `tee` 를 붙여 달라는 부탁도 매번 드릴 수
없다. 그래서 **이 파일이 자기 출력을 알아서 남긴다.**

돌리는 방법은 그대로다.

```
pt_shell> source .../pt/xtalk_all.tcl
   ->  <현재폴더>/xtalk_all_run.log
```

방법: 맨 위에서 자기 자신을 `redirect -tee` 안에서 한 번 더 `source` 한다.
두 번째 진입에서는 `XT_LOGGING` 이 이미 있으므로 그 블록을 건너뛰고 본문을
실행한다. `-tee` 라 화면에도 그대로 나온다.

**Tcl 에러도 잡아서 로그에 적는다.** `errorInfo` 전체를 로그 끝에 붙이므로
`while executing` / `(file ... line N)` 까지 남는다. 지금까지는 이게 화면에만
떠서 받는 쪽에 전달되지 않았다.

이제 코너 폴더에 이렇게 남는다.

```
<코너>/
  <코너>.rpt
  xtalk_all_run.log                       <- 화면 그대로
  <db이름>/xtalk/run_info.txt             <- 실행 조건 + 완주 여부
  <db이름>/xtalk/ (결과 4개)
```

**실제 PT 로 검증했다** (BoomCoreV3 / TT_0p7V_25C / `pt_shell V-2023.12-SP4`).
정상 코너는 `OK-XTALK` 까지 전부, 리포트를 못 찾은 코너는 `E-NORPTFILE` 블록이
`looked in :` 경로와 그 폴더의 `.rpt` 목록까지 그대로 로그에 남았다.

hold 판도 `dev/make_hold.py` 로 다시 만들었다. 두 tcl 은 재전달이 필요하다.

### 0_trim: 전압이 섞인 경로를 **세기 전에** 버린다 (`--voltage`)

담당자분이 리포트 핀 줄 오른쪽 끝에 전압 열을 붙여 주시기로 했다. 코너 이름은
0.78V 인데 특정 macro/cell 만 다른 전원의 db 가 물린 구조라, 경로 하나가 전압
두 개를 지나갈 수 있다. 그런 경로는 코너를 쓸어도 macro 쪽이 안 따라 움직여서,
표시 없이 섞으면 모델이 그 차이를 전압 효과로 잘못 배운다.

**순서가 중요하다.** 세고 나서 거르면 `--keep 10000` 이 10000개보다 적게 남는다.
그래서 **거르고 나서 센다.** 이제 `--keep 10000` 은 '단일 전압 10000개' 다.

```
python3 0_trim.py --dir round1/corners --keep 10000 --voltage auto   # 코너 이름에서
python3 0_trim.py --dir round1/corners --keep 10000 --voltage 0.78   # 값 고정
python3 0_trim.py --dir round1/corners --keep 10000                  # 전압 안 봄(예전 그대로)
```

**목표 전압은 코너마다 따로 정한다.** 0_trim 은 코너를 한꺼번에 돌기 때문에 값
하나로 고정하면 안 된다. `--voltage auto` 면 코너(파일) 이름에서 읽는다:
`tt0p78v25c` -> 0.78, `TT_0p7V_25C` -> 0.7. 못 읽으면 `E-VNAME` 으로 멈춘다.

화면에 깔때기가 나온다.

```
  코너                    전압    원래   남김  mixed  전압없음  다른전압
  tt0p78v25c_Cnom        0.78       ?     30     16        0        0
  tt0p9v25c_Cnom          0.9       ?     30      7        0        0
```

| 판정 | 뜻 |
|---|---|
| 남김 | 코너 전압 하나뿐 |
| mixed | 전압 두 개 이상. macro 등 다른 전원을 지나감 |
| 전압없음 | 값을 하나도 못 읽음. **전부 이 칸이면 열 이름이 실제와 다른 것** |
| 다른전압 | 하나인데 코너 전압이 아님 |

**열 이름은 아직 미정이다.** 정해지면 `0_trim.py` 맨 위 한 줄만 고치면 된다.

```python
VOLT_NAMES = ("volt", "voltage", "vdd")
```

머리말에서 이 이름을 찾아 **글자 위치**를 얻고 그 자리의 값을 읽는다
(`2c_merge.py` 가 열을 맞추는 방식과 같다). 열이 몇 개 더 붙어도 안 흔들리고,
전압이 핀 줄에 붙든 넷 줄에 붙든 상관없다 -- 줄 종류를 안 가리고 그 열에 숫자가
있으면 읽고 없으면 넘어간다. 그래서 `(net)` 줄의 Path 값을 전압으로 잘못 읽지도
않는다(열 범위 밖 숫자는 무시).

메모리는 그대로다. 경로마다 들고 있는 것은 slack 8바이트 + 통과 여부뿐이다.
`--voltage` 를 안 주면 1차 읽기가 예전처럼 slack 만 보므로 속도도 그대로다.

검증: 전압 열을 붙인 리포트 2코너(0.78V / 0.9V, 경로 200·300개, 5경로마다 한
핀을 0.90 으로)로 `--keep 30 --voltage auto` 를 돌렸다. mixed 를 16개·7개 버리고도
**30개씩 남았고**, 잘라 낸 파일을 다시 뜯어 보니 전압이 섞인 경로 0개, 나온 전압이
각각 `['0.78']` / `['0.90']` 하나씩이었다. `--voltage` 없이 돌린 결과는 예전과
동일했다(3코너 x 50 = 150개).

### xtalk_all: 남의 디자인 리포트를 읽고 도는 일을 막는다

현장에서 PERI 를 돌린 pt_shell 그대로 MFC 를 돌렸더니, **앞 디자인 리포트 경로가
세션에 남아** MFC 폴더에 PERI 넷으로 만든 결과가 들어갔다. 에러도 경고도 없이
끝까지 돌아서, 한참 뒤에야 알았다.

**(1) 아무것도 기억하지 않는다**

- `$OUT` 분기를 없앴다. `fixed_paths.tcl` 이 남긴 세션 변수인데 아무도 안 지워서
  다음 디자인·다음 코너까지 따라왔다. 없애도 잃는 것이 없다 -- `$OUT` 은
  `"$CORNER.rpt"` 라는 상대 이름이라 리포트가 현재 폴더에 떨어지는데, 뒤이은
  폴더 스캔도 현재 폴더를 본다. `$OUT` 이 찾던 파일은 폴더 스캔도 반드시 찾는다.
- `XT_RPT` / `XT_DIR` 은 **쓰고 바로 `unset`** 한다(일회용).

**(2) 그래도 어긋나면 시작 전에 멈춘다 -- `E-DESIGNMISMATCH`**

리포트 머리말에는 `Design : <이름>` 이 박혀 있고 PT 에는 `current_design` 이 있다.

```
    what   : that report was made from a different design.
             report says   : PERI
             loaded design : BoomCore
    code   : E-DESIGNMISMATCH
```

**실제 PT 로 검증했다** (BoomCoreV3, TT_0p7V_25C, `pt_shell V-2023.12-SP4`).

Dist/Res 는 **드라이버 핀에서 그 리시버 핀까지**의 값인데, 넷 이름만 키로 쓰면
넷 하나에 값이 하나뿐입니다. 리시버가 여럿인 넷은 그 줄들이 전부 같은 값을 받습니다.

| 표의 열 구성 | SPEF 계산값과 일치 |
|---|---|
| `net_name res dist` | 79.5% |
| `net_name driver_pin receiver_pin res dist` | **100%** |

(`example/round2/TT_0p8V_25C`, (net) 8,930줄 기준)

그래서 상대에게 **driver/receiver 핀 열 2개를 더** 달라고 하는 게 좋습니다. 열 이름에
driver/receiver(또는 drv/recv/load/sink)가 들어 있으면 자동으로 핀 쌍 키로 바뀝니다.
3열로 받아도 돌아가긴 합니다 -- 대신 영향 받는 줄 수를 `W-NETKEY` 로 매번 알려줍니다.

### 표는 온도마다 따로 받아야 합니다

같은 디자인에서 실측한 결과입니다((net) 82,472줄).

| 축 | Dist | Res |
|---|---|---|
| 전압 (0.6V->0.8V) | 안 변함 | **안 변함** |
| RC 코너 (Cmin->Cmax) | 안 변함 | 83% 가 0.1% 미만 |
| 온도 (25C->125C) | 안 변함 | **전 넷 +39%** |
| 온도 (-40C->125C) | 안 변함 | **전 넷 +86%** |

`R(T) = R(0C) x (1 + 0.00432 x T)` (구리 TCR 0.43%/도) 로 잘 맞습니다.

- **Dist 는 표 1개면 됩니다.** 배치 좌표라 코너가 바뀌어도 안 변합니다.
- **Res 는 온도마다 표가 따로 있어야 합니다.** 한 개를 돌려 쓰면 배선 RC 의
  온도 의존성이 사라지고, 그 효과가 트랜지스터 코너 쪽으로 잘못 귀속됩니다.
- **전압별로는 필요 없습니다.** 17개 전압 코너가 있어도 표는 온도 3개분입니다.

같은 온도의 코너 폴더들에는 같은 파일이 들어갑니다. 링크로 거는 편이 편합니다.

```csh
foreach D (round2/TT_*_25C)
    ln -s /받은곳/distres_25c.txt $D/resdist_map.txt
end
```

### SPEF 를 코너 이름 보고 알아서 고른다

전에는 SPEF 파일 하나를 손으로 지정해야 했습니다. 코너마다 온도나 RC 코너가
다르면 코너 폴더에 `design.spef` 를 일일이 걸어야 했고, 틀려도 티가 안 났습니다.

이제 폴더째 주면 코너에 맞는 것을 고릅니다.

```bash
python3 2b_distres.py    --dir setup/tt0p6v25c_Cnom --spef-dir setup
python3 4_all_corners.py --root setup --spef-root setup
```

**온도와 RC 코너(BEOL)로만 맞춥니다. 전압은 안 봅니다.** 기생 RC 는 배선
형상과 온도로 정해지고 전원 전압과는 무관하기 때문입니다. 그래서
`tt0p6v25c_Cnom` / `tt0p7v25c_Cnom` / `tt0p8v25c_Cnom` 은 같은 SPEF 를 씁니다.

```
코너 이름  tt0p6v25c_Cnom          ->  25C, Cnom
SPEF 이름  ....Cnom_model_25.spef  ->  25C, Cnom     ... 짝
```

파일 이름끼리 맞추고, 이름으로 안 갈리면 SPEF 머리말을 읽습니다.

```
// PARASITIC_TECH Cnom_model at 25.000 degree
```

**애매하면 아무거나 고르지 않고 멈춥니다** (`E-SPEFPICK`). 틀린 SPEF 로 돌면
숫자가 그럴듯하게 나와서 한참 뒤에야 드러나고, 그때는 되돌리기가 더 비쌉니다.
`4_all_corners.py` 는 **한 코너라도 못 고르면 아무 코너도 돌리지 않습니다.**

돌리기 전에 짝만 확인하는 명령 (SPEF 를 안 읽어서 즉시 끝납니다):

```bash
python3 _engine/spef_match.py --spef-dir setup --dir setup
```

```
  코너                    물릴 SPEF                              근거
  tt0p6v25c_Cnom         boomcorev3.Cnom_model_25.spef          cnom 25C
```

### 5b: 화면 출력 영어로, 그리고 어느 입력이 잘못됐는지 짚어 준다

화면에 나가는 문장을 영어로 바꿨습니다. 터미널이 한글을 깨뜨려서 정작
필요할 때 진단문을 못 읽었습니다. 주석과 docstring 은 한국어 그대로입니다 --
화면에 안 나오므로 안 깨집니다.

그리고 `E-PARSE` 가 무슨 일이 있었든 "`context_raw.rpt` 앞부분을 보라"고
했는데, 5b 는 파서에 입력을 셋 넘기면서 그중 하나만 확인하고 있었습니다.
그래서 5a 쪽이 문제여도 멀쩡한 PT 리포트를 뒤지게 됐습니다.

| 코드 | 언제 | 무엇을 하면 되나 |
|---|---|---|
| `E-NO5A` | 5a 결과(`path_victim_nets.tsv`, `unique_contexts.tsv`)가 없거나 빔 | 5a 를 먼저. `xtalk_all.tcl` 은 앞 파일을 안 만듭니다 |
| `E-MODE` | PT 출력의 setup/hold 가 `--mode` 와 반대 | `--mode` 를 바꾸거나 PT 를 다시 |
| `E-NORAW` | `context_raw.rpt` 가 없거나 **빔** | 빈 것은 디자인을 안 올린 채 tcl 을 돌린 경우 |
| `E-PARSE` | 그 밖 | 파서 메시지가 배너 위에 찍힙니다. 그걸 먼저 |

`E-MODE` 는 현장에서 제일 흔합니다. setup 으로 만든 출력에 `--mode hold` 를
주는 경우입니다.

```
[ FAILED ] The PT output was made with a different mode.
           5b was told  --mode hold
           but context_raw.rpt holds the other kind of delta delay.
           Either re-run 5b with:   --mode setup
```

시작할 때 두 입력의 줄 수와 mode 를 찍어서, 돌기 전에 어긋남이 보입니다.

```
  PT output : .../context_raw.rpt  (2.9MB)
  5a input  : path_victim_nets.tsv (8930 rows), unique_contexts.tsv (788 rows)
  mode      : setup   (must match the xtalk_all run)
```

`E-NOENGINE` 은 `_engine/` 이 **왜** 빠지는지까지 말합니다. 이름이 밑줄로
시작해서 `cp *.py` 나 `scp *` 가 조용히 두고 가는 것이 매번 원인이었습니다.
