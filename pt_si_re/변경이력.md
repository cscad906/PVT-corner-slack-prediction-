### SPEF 를 코너 이름 보고 알아서 고른다

전에는 SPEF 파일 하나를 손으로 지정해야 했습니다. 코너마다 온도나 RC 코너가
다르면 코너 폴더에 `design.spef` 를 일일이 걸어야 했고, 틀려도 티가 안 났습니다.

이제 폴더째 주면 코너에 맞는 것을 고릅니다.

```bash
python3 2b_distres.py    --dir setup/tt0p6v25c_Cnom --spef-dir setup
python3 4_all_corners.py --root setup --spef-root setup
```

**온도와 RC 코너(BEOL)로만 맞춥니다. 전압은 안 봅니다.** 기생 RC 는 배선
형상과 온도로 정해지고 전원 전압과는 무관하기 때문입니다. 그래서
`tt0p6v25c_Cnom` / `tt0p7v25c_Cnom` / `tt0p8v25c_Cnom` 은 같은 SPEF 를 씁니다.

```
코너 이름  tt0p6v25c_Cnom          ->  25C, Cnom
SPEF 이름  ....Cnom_model_25.spef  ->  25C, Cnom     ... 짝
```

파일 이름끼리 맞추고, 이름으로 안 갈리면 SPEF 머리말을 읽습니다.

```
// PARASITIC_TECH Cnom_model at 25.000 degree
```

**애매하면 아무거나 고르지 않고 멈춥니다** (`E-SPEFPICK`). 틀린 SPEF 로 돌면
숫자가 그럴듯하게 나와서 한참 뒤에야 드러나고, 그때는 되돌리기가 더 비쌉니다.
`4_all_corners.py` 는 **한 코너라도 못 고르면 아무 코너도 돌리지 않습니다.**

돌리기 전에 짝만 확인하는 명령 (SPEF 를 안 읽어서 즉시 끝납니다):

```bash
python3 _engine/spef_match.py --spef-dir setup --dir setup
```

```
  코너                    물릴 SPEF                              근거
  tt0p6v25c_Cnom         boomcorev3.Cnom_model_25.spef          cnom 25C
  tt0p8v25c_Cmax         boomcorev3.Cmax_model_25.spef          cmax 25C
  전부 짝이 맞습니다.
```

고르는 순서는 `design.spef` > `--spef-root` > `--spef` 이고, 예전 동작은
그대로입니다. `--spef-root` 는 `--root` 와 같은 폴더여도 됩니다. 코너 탐색은
`.rpt` 를 가진 하위 폴더만 보므로 같은 자리의 `.spef` 와 섞이지 않습니다.

### 4_all_corners: 어디까지 왔고 어디서 걸렸는지 보인다

코너 16개 x 4단계면 화면이 길어서 진행 상황도 실패 지점도 스크롤에 묻혔습니다.

도는 중:

```
[3/16] tt0p7v25c_Cnom   남은 시간 약 24분
  2a cpin      끝 (12초) [ OK-CPIN ]
  2b distres   끝 (1분 12초) [ OK-DISTRES ]
  -> tt0p7v25c_Cnom 끝. 걸린 시간 1분 30초
```

끝나고:

```
코너별 결과   (전체 18분 4초 걸림)
  정상 15 / 문제 1 / 전체 16 코너

걸린 곳  (1건)
  tt0p6v25c_Cnom   2b distres   E-RES0   SPEF 에서 Res 를 하나도 못 구함
                                         -- SPEF 가 이 코너 것이 맞는지
  그 코너만 따로 돌려 화면을 보려면:
    python3 .../2b_distres.py --dir setup/tt0p6v25c_Cnom
```

`걸린 곳` 에는 실패(`E-`)뿐 아니라 **경고(`W-`)도** 모입니다. `W-RES` 같은
것은 결과 파일이 나와도 데이터가 불완전하다는 뜻이라, 놓치면 나중에 모델
쪽에서야 드러납니다.

### 5b: 화면 출력 영어로, 그리고 어느 입력이 잘못됐는지 짚어 준다

화면에 나가는 문장을 영어로 바꿨습니다. 터미널이 한글을 깨뜨려서 정작
필요할 때 진단문을 못 읽었습니다. 주석과 docstring 은 한국어 그대로입니다 --
화면에 안 나오므로 안 깨집니다.

그리고 `E-PARSE` 가 무슨 일이 있었든 "`context_raw.rpt` 앞부분을 보라"고
했는데, 5b 는 파서에 입력을 셋 넘기면서 그중 하나만 확인하고 있었습니다.
그래서 5a 쪽이 문제여도 멀쩡한 PT 리포트를 뒤지게 됐습니다.

| 코드 | 언제 | 무엇을 하면 되나 |
|---|---|---|
| `E-NO5A` | 5a 결과(`path_victim_nets.tsv`, `unique_contexts.tsv`)가 없거나 빔 | 5a 를 먼저. `xtalk_all.tcl` 은 앞 파일을 안 만듭니다 |
| `E-MODE` | PT 출력의 setup/hold 가 `--mode` 와 반대 | `--mode` 를 바꾸거나 PT 를 다시 |
| `E-NORAW` | `context_raw.rpt` 가 없거나 **빔** | 빈 것은 디자인을 안 올린 채 tcl 을 돌린 경우 |
| `E-PARSE` | 그 밖 | 파서 메시지가 배너 위에 찍힙니다. 그걸 먼저 |

`E-MODE` 는 현장에서 제일 흔합니다. setup 으로 만든 출력에 `--mode hold` 를
주는 경우입니다.

```
[ FAILED ] The PT output was made with a different mode.
           5b was told  --mode hold
           but context_raw.rpt holds the other kind of delta delay.
           Either re-run 5b with:   --mode setup
```

시작할 때 두 입력의 줄 수와 mode 를 찍어서, 돌기 전에 어긋남이 보입니다.

```
  PT output : .../context_raw.rpt  (2.9MB)
  5a input  : path_victim_nets.tsv (8930 rows), unique_contexts.tsv (788 rows)
  mode      : setup   (must match the xtalk_all run)
```

`E-NOENGINE` 은 `_engine/` 이 **왜** 빠지는지까지 말합니다. 이름이 밑줄로
시작해서 `cp *.py` 나 `scp *` 가 조용히 두고 가는 것이 매번 원인이었습니다.
